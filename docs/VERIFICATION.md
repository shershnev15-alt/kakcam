# Verification and public admission

Статус: полный Claim Profile, защищённые файлы, Steam OpenID, FACEIT OAuth, Sumsub KYC, модерация и ручное решение о публикации реализованы. По умолчанию любой игрок и его PPR закрыты. Публичная выдача включается только после одновременного выполнения всех обязательных условий.

## Обязательные условия

1. Игрок самостоятельно создал claim, а модератор подтвердил владение профилем.
2. К claim приложено обязательное restricted-фото; наружу отдаётся только отдельная одобренная WebP-копия через `/api/v1/media/players/*`.
3. Аккаунт Steam для CS2 привязан и имеет `verifiedAt` от провайдера.
4. Аккаунт FACEIT для CS2 привязан и имеет `verifiedAt` от провайдера.
5. Внешний KYC-провайдер подтвердил документ, совпадение лица и liveness; сохранено подписанное webhook-решение, но не копия документа.

Условия соединены через AND. Отсутствие или отзыв любого сигнала немедленно исключает игрока из каталога, поиска, PPR, sitemap, составов команд, ленты переходов и персональной статистики матчей. Detail API отвечает одинаковым `404` для неизвестного и закрытого профиля, поэтому публичный интерфейс не подтверждает наличие скрытой записи.

## Два независимых решения

Первичная модерация claim проверяет, что пользователь действительно владеет профилем, и создаёт Verification level 2. Это ещё не даёт публичного доступа.

Публикацию или отзыв выполняет роль с `player.publish` после проверки всех обязательных сигналов. Роль выполняется в рамках административной модерации. Решение создаёт отдельные `Verification` level 4 и `PlayerPublication`, требует основание и фиксируется в `AuditLog`.

## Фото и приватность

Исходный файл хранится как приватный AES-256-GCM blob, связанный с `VerificationEvidence` и `visibility=RESTRICTED`; в публичный DTO и аудит попадают только тип, размер, checksum и результат сканирования. Pipeline проверяет magic bytes и размер, отклоняет неподдерживаемые форматы, декодирует и повторно кодирует изображения без EXIF/геолокации, вызывает malware scanner и создаёт отдельную WebP-копию для публикации. В production обязательны внешний антивирус, уникальный ключ из secret manager, резервирование private volume/object storage и утверждённая retention/удаление policy.

## Steam и FACEIT

Публикационная policy учитывает только записи `PlayerGameAccount` для игры `cs2`, провайдеров `STEAM` и `FACEIT` и с непустым `verifiedAt`. Ручного обхода этого условия в endpoint публикации нет.

Steam привязывается через OpenID 2.0 callback, одноразовый state и серверный `check_authentication`; обычный lookup публичного профиля не выставляет `verifiedAt`. FACEIT использует Authorization Code + PKCE S256, одноразовый state и backend token exchange. Повторное использование callback и привязка одного внешнего аккаунта к двум игрокам блокируются. Email подтверждается одноразовым SHA-256 token со сроком 24 часа; в production письмо отправляется через Resend или совместимый webhook-провайдер, без подтверждения claim не создаётся.

## Face ID и документы

Кабинет создаёт короткоживущую Sumsub WebSDK-ссылку для документа, selfie/face match и liveness. API принимает только webhook с валидной HMAC-SHA256/512 подписью и хранит applicant/check ID, статус, review answer и reject labels; копии документов у cyberID не сохраняются, если пользователь отдельно не загрузил доказательство. `GREEN` создаёт identity verification, `RETRY` возвращает заявку на исправление, окончательный отказ блокирует одобрение. Биометрия, consent, residency, сроки хранения, трансграничная передача, удаление и ручная апелляция требуют юридического решения до live-запуска. Финальную публикацию подтверждает внутренний модерационный процесс после проверки всех сигналов.

## Уровни

0 Unverified; 1 Account Connected; 2 Identity Verified; 3 Organizer Verified; 4 Official Verified; 5 Platform Verified.

Уровень относится прежде всего к утверждению о конкретном поле. Badge профиля — агрегированное представление, которое не делает все поля одинаково достоверными и само по себе не открывает профиль.

## Effective value

Источник создаёт `FieldAssertion(entity, field, value, source, observedAt, author, level)`. Resolver выбирает effective assertion по политике поля: trust tier, свежесть, полнота и ручное решение. Конфликт не уничтожает прежнее значение и создаёт moderation case.

## Состояния claim

`submitted → evidence_requested → review → approved/rejected`. Методы: connected game account, social challenge code, organizer/team confirmation. Модератор видит отдельные статусы email, KYC, Steam/FACEIT и безопасные ссылки на restricted evidence; может запросить исправления, отклонить или одобрить. Одобрение невозможно без фото, Steam, FACEIT и KYC.
